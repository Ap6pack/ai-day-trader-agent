# Review evidence archive

The raw reproduction probes written during two independent reviews of commit
`d6e0768`. They are kept here as the record behind the findings; the ones worth
running on every change were rewritten as proper regression tests under
[`tests/regressions/`](../../tests/regressions/), which is where you should
start. [`tests/regressions/FINDINGS.md`](../../tests/regressions/FINDINGS.md)
maps each finding id to its test.

## Why these are not tests

**These probes are deliberately excluded from CI.** 28 of the 73 bind sockets,
spawn child processes, or drive `requests` directly, and several configure a
LIVE Alpaca account mode to exercise the real-money code paths. They were safe
when run because the transport was stubbed in-process — but that safety is a
property of how they were invoked, not of the files, so they must not be
collected automatically.

Two things keep them out:

- `pytest.ini` sets `testpaths = tests`, so `docs/` is never collected.
- No file here is named `test_*`, so pytest would not collect them even if that
  changed.

Do not move them into `tests/`. If a probe is worth running repeatedly, port it
to `tests/regressions/` with the offline harness in that package's `conftest.py`.

## Sanitisation

- No real credential was ever present; the probes used fabricated values. Those
  were still normalised to `PLACEHOLDER_KEY_ID` / `PLACEHOLDER_SECRET`.
- Account figures, positions and order ids in these probes are **fabricated
  fixture data**, not from any real account.
- `.log` and `.db` probe output (230 and 19 files) is **not** archived: it is
  bulky, it is regenerated by re-running a probe, and `.gitignore` blocks both
  patterns anyway.
- Absolute session paths were rewritten to repository-relative ones.

## Running a probe

They expect the project importable and a virtualenv with the project
requirements:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=. python docs/evidence/probes/A_stop_race.py
```

Before running any of them, confirm containment — several set
`ALPACA_TRADING_BASE_URL` and `ALPACA_LIVE_TRADING` to reach live-mode code:

```bash
python -m trader.status      # expect mode review, account_mode paper, newsbot off
```

Run them on a machine with **no Alpaca credentials configured**. A probe that
stubs its transport cannot reach a broker; one whose stub you have edited can.

## What is here

Probes are prefixed by the claim group they belong to. `*rev_*` and `SKEP*`
prefixes are the adversarial re-verification runs, which rebuilt a finding
independently rather than reusing the original author's harness.

| Prefix | Claim group | Count |
|---|---|---|
| `A_`, `A1rev_` | Autopilot stop/start, orphaned workers | 13 |
| `B_`, `SKEPTIC_B1_` | `flatten_owned` double-sell, orphaned entries | 5 |
| `C_`, `C1rev_`, `SKEP_C1a_` | Live daily-cap races and accounting | 21 |
| `D_` | Demo and stale data reaching live orders | 5 |
| `E_` | News bot supervisor lifecycle | 10 |
| `SKEPTIC_F1_` | Desk browser access | 9 |
| `G_` | Order guard: review gate, non-finite config | 7 |
| `H_` | Scoring window, flatten accounting | 3 |
| `I_` | Signal fusion, dividend capture lifecycle | 12 |

Several probes import a shared harness from a sibling file (`A_common.py`,
`C_fake_alpaca.py`, `C_broker_server.py`), so run them from the repository root
with `PYTHONPATH=.` and keep the directory intact.
